# Triton surface preparation

The checked-in Triton derivatives are generated by
`node scripts/prepare-triton-surface.mjs --rebuild` from the ignored original
under `output/surface-originals/`. Refresh it with `--download`; rebuilding
verifies the pinned SHA-256 before writing runtime assets.

## Official mapped source

The source is the USGS Astrogeology [Triton Voyager 2 Global Color Mosaic
600m](https://astrogeology.usgs.gov/search/map/triton_voyager_2_global_color_mosaic_600m),
assembled from NASA Voyager 2 imagery by NASA/JPL and the Lunar and Planetary
Institute. The pinned GeoTIFF is 14,138×7,069, 8-bit RGB at 600 m/pixel. Its
native map is equirectangular, planetocentric, north-up, east-positive, and
covers -180..180 degrees. The source hash and URL are recorded in
`assets/surfaces/triton-manifest.json`.

The mapped coverage is uneven because Triton was observed during a flyby; the
official global-fill product preserves that limitation and fills map gaps with
neighboring pixels. It is still the actual mapped product, not a generated
appearance.

## Orientation and relief policy

No reliable complete global Triton DEM is bundled. Color is never interpreted
as height. Medium and near height files contain a bounded seamless synthetic
field generated solely from the 3D unit direction vector, encoded as
little-endian uint16 with `height = -512 + sample × 1` meters. It is explicitly
an approximation, not measured Triton topography.

The runtime canonical physics radius is 1,352,600 m, while the source map
metadata uses 1,350,000 m. Both values and their difference are retained in the
manifest rather than silently substituting one for the other.

## Derived levels

Preview is color-only at 512×256. Medium is 1024×512 and near is 2048×1024;
both include matching height files. JPEG derivatives use quality 88 and 4:4:4
chroma. Asset dimensions, decoded height ranges, and SHA-256 hashes are
recorded in `assets/surfaces/triton-manifest.json`.
